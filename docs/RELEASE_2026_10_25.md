Stop backend/frontend first. Extract this ZIP to a separate folder. Run its updater against the existing project; do not overwrite your project by dragging entire folders together.


### Freshness outside the server

Set REPOLENS_FRESHNESS_SCHEDULER=external in `.env` and restart. On macOS:

```bash
source .venv/bin/activate
python scripts/freshness_worker.py --once
python scripts/install_freshness_schedule.py --write
# The command prints the exact plist path. Use that path in the next command:
launchctl bootstrap gui/$(id -u) /Users/you/Library/LaunchAgents/dev.repolens.freshness.HASH.plist
```

Use the printed filename, not the example HASH. The worker wakes every five minutes, checks records due at six hours and retries failures after 15 minutes. For always-on Linux hosting, supervise `python scripts/freshness_worker.py` as a separate service with the same persistent database, working directory and `.env`. Keep only one logical schedule; leases prevent overlap. A sleeping/off computer cannot run checks. To accept live behavior: index your test repository, push a commit, click Check now (or wait for due time), verify stale, reindex, check again and verify current. Check the workspace's separately pinned snapshot too: it may correctly remain stale until reshared.
